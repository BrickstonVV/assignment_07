In this assignment I learned that each website needs its own scraping approach. On Lakeshore Lattes I used class selectors and the sibling selector (~) to get from each heading to its cards, then cleaned the inner_text. On Hilltop Grind I used an id selector, read_html and melt to turn the size columns into rows. Canal Street Coffee was the hardest. I had to drive a headless browser, wait for the JavaScript to load, handle pagination with Show more, and crawl each item’s link. What surprised me most was how much one melt call could do: it turned a wide table with separate S, M and L price columns into one row per item and size, which is exactly the shape the rest of the analysis needed.  For matching, I learned that normalization and fuzzy matching handle most name differences, but a threshold alone can’t tell what a drink actually is. Matcha Latte scored 87 against Mocha Latte but is a different drink, while PSL scored only 18 and is the same as Pumpkin Spice Latte. That’s why a human in the loop matters: a score only measures spelling, so a person has to decide what the item really is, and saving those answers means the code never asks the same question twice. Then I used a merge indicator for the gap analysis, and the result that stood out was that avocado toast is sold by all three rivals but not by us, which makes it the strongest hint about what to add.  The part I struggled with most was the Show more loop on Canal Street. I understand that it counts the cards, clicks, and then uses wait_for_function to wait until more cards appear, but I couldn’t yet write that loop from memory. Next, I plan to practice it by scraping a real site that has a Load more button and writing the wait myself instead of copying it.
